# RTX 4090 评测：基线与性能验收

截至 2026-11-18，Sim 5.1 四环境采图已跑通。图像一致性、逐布局闭环成绩和实际吞吐仍需验收。
隔离配置适用于实验复现。

## 已确认的 PR #26 基线

[PR #26](https://github.com/xstar-org/RoboDojo/pull/26) 当前 head 为
`44b5ecf46e6727c1a312995e2060c0c2ec17084b`，base 为 `xstar-main`，依赖 #23。
其 `independent_isolated` 逐环境隐藏邻居几何、停用邻居灯，
`isolated_owner_products_only: true` 只更新当前环境的 product。
原实现拒绝在 Sim 5 启用该后端。
正式测速分母使用同版本的 PR #26 单环境路径。该路径默认等待一次出帧，并在评测入口启用 zero-delay 设置。

N56 job 1805350 的三份 camera backend 源文件与 PR #26 head **逐字一致**。
固定动作带 SHA256：
`8d01cbfdf9f66e43cb9344faff3360f1fdcad95bf41aaee41746fb85e951f5e8`。
原始目录：`/data/run01/scxm005/robodojo-eval/render-throughput-benchmark-20261112`。
Isaac Sim 6.0.0.1 / Lab 2.3.2，640×480 三相机、PT64、两次 delivery，
96 个动作，每个动作后采图；不含策略推理，关闭视频。
探针还额外启用了头相机深度、固定目标世界原点与 bottle rigid intervention；
因此这些数字不是未经干预的官方评测吞吐。

| 路径 | 动作中位数 | 采图中位数 | 总步骤中位数 | 96 步等长回放 episode/h |

episode/h 使用 **实际总耗时** 换算，不能用步骤中位数代替总耗时。

4-env 正确版的动作均值占总耗时约 4.8%，仅优化物理/IK 无法获得显著收益。
PR #26 的 2.75 → 1.20 秒属于隔离路径内部微基准。

## Sim 5 候选改动

目标固定为 Isaac Sim 5.1.0 / Lab 2.3.2。官方测试 Linux 驱动为
[580.65.06](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/installation/requirements.html)。
N56 早先节点读数为 580.82.07，已做过 Sim 5.1 合成场景启动；
每次分配仍需重新记录驱动、CUDA/Vulkan PCI 映射和实际启动结果。
`CUDA_VISIBLE_DEVICES` 不能替代 Vulkan GPU 的 PCI 匹配。

本候选允许 Sim 5.1 使用隔离路径。Sim 5.1 在采图期间固定 USD session layer 列表，
仅临时写入邻居的可见性和灯光激活字段，并在采图结束时恢复，避免使已初始化的 PhysX 视图失效。
Sim 6 继续使用已有的临时子层方案。

```yaml
# env_cfg/camera/<camera>.yml；仅用于隔离实验配置
render_product_backend: independent_isolated
isolated_owner_products_only: true
multi_env_capture_render_passes: 1
```

`multi_env_capture_render_passes` 默认为 **2**，保持原有渲染次数。
候选 1-pass 用于检查是否能省去冗余帧；dispatcher delivery 只能证明帧已交付，
不能证明 PT/去噪收敛或灯光切换后的像素等价。
单环境继续使用 observation 的 `capture_render_passes`，不受这个新键影响。
缺少 zero-delay 设置时，原同步器仍自动多等一次 delivery。
dispatcher 停滞超时现在抛异常，避免把旧缓冲区当作当前图像继续评测。

## 验收顺序与退出条件

1. 在同一 Sim 5.1 版本、相同实际渲染设置下重新跑 1-env 基线，
   不能拿 Sim 6 的单环境速度作为 Sim 5 候选的分母。读取实际 spp/totalSpp、
   AA、去噪、分辨率、深度 annotator、相机位姿与物理/粒子初始状态。
2. 对比 4-env 隔离的 2-pass 与 1-pass，固定 layout 世界坐标。
   覆盖全部槽位、三路相机、0/32/64/96 步、正逆采集顺序和恢复。
   同时保存 1-env 的 1-pass/2-pass 噪声对照；先约定误差阈值，
   以已有 Sim 6 的 0.019–0.026 MAE 为参考，不能只检查非黑图。
   1-pass 如果引入帧滞后、图像残差或恢复失败，就淘汰该方案。
3. 用同权重、seed、layout 和策略配置跑配对闭环。逐布局核对成功与进度分，
   同时保留成功率、平均分、不稳定布局和实际执行布局。
4. 图像与闭环成绩通过后，在同一张卡串行重复测速，分别记录动作、采图、重置、
   推理和总耗时，同时记录 GPU 利用率与显存。闭环吞吐用实际完成的唯一 layout 数和总耗时计算。
   两组使用相同的视频录制设置。

回放门槛工具使用已完成目录中的 `benchmark.json` 和 `runtime-profile.json`：

```bash
python scripts/compare_replay_throughput.py runs/sim51-one runs/sim51-four --min-speedup 1.5
```

退出码 0 表示回放吞吐达标，1 表示低于门槛，2 表示数据不完整或不可比。
工具拒绝不同 runtime、不同动作带、不同实际 render profile、失败/未完成的记录。
它不替代相机正确性、相同硬件/场景配置检查或闭环验收。

如果单卡 PT64 已接近像素计算上限，增加环境数并不保证线性加速。
后续应测独立 1-env 进程/卡的集群横向扩展及集中策略推理，
同卡多进程需单独测显存和吞吐；现有静态方块结果只支持图像控制。
不要用减少 spp、换渲染器或重复同一 layout 的 load test 冒充等价评测提速。

## Sim 5.1 验证进度

2026-11-18，N56 四卡作业 `1827888` 已完成 Sim 5.1 四环境采图冒烟测试。
同一倒水布局、同世界坐标的 RGB 回放中，布局 10 右腕在两次出帧下仍有 1.73–1.76/255 的平均像素绝对差。

原生 PT16 闭环试跑使用同一份 RGB60k 权重和四个布局。两组都等待两次出帧。
单环境成功率与平均分分别为 25% 和 25/100，四环境为 50% 和 50/100。
其中布局 10 从成功变为失败，布局 8 和 9 从失败变为成功。单环境复测复现了全部四个布局的结果。

随后用 PR #26 的单环境默认一次出帧，对比本 PR 最新四环境代码的两次出帧。
在相同的四个布局上，两组均为 25% 成功率、25/100 平均分，且逐布局一致。
布局 10 两组都成功。首帧 RGB 仍有差异，布局 10 的右腕 MAE 为 2.30/255，
相同布局的两次单环境对照为 0.48/255。布局 11、9、8 的右腕 MAE 分别约 1.18、1.14、1.14/255，
对应单环境对照约 0.03/255。该结果只覆盖这四个倒水布局的一次配对闭环。
这次同卡闭环的客户端进程墙钟为 507.72 秒和 418.81 秒，分别为 28.36 和 34.38 episode/h（1.21 倍）。
墙钟包含客户端启动、重置、仿真及策略调用，策略服务启动在计时区间之外。图像一致性和可复现提速仍待验收。

邻居灯消融在同一张 4090 的四环境上固定 PT64、两次出帧、邻居几何隐藏和 owner-only product 更新。
三个动作检查点各做两组配对。停用与保留邻居灯分别为 2.740 和 2.720 秒/owner，差约 0.8%。
停用灯光增加的 USD 编辑与恢复合计约 2.3 毫秒/owner。这个范围内主要开销仍在等出帧。
这组诊断支持保留现在的灯光隔离，并将性能优化优先放在原生评测链路的重复工作上。

在同一四环境 PT16 闭环中，`env_cfg/sim/sim_config.yml` 的 `eval_reset_capture_count`
可保留最后指定次数的重置预热采图。默认 40 次，所有设置均执行相同的 200 步预热物理。
两次配对交换了试验顺序。设为 4 时，两次均与本次对照的四布局成绩逐项一致。
重置分别节省 28.51 和 24.58 秒，客户端总墙钟分别从 429.98 降到 400.64 秒、
从 463.33 降到 411.89 秒（吞吐 1.073 和 1.125 倍）。第二次由本 PR 提交的代码直接执行。
两次配对共有 24 个布局和视角组合，其中 23 个首帧 MAE 落在四次原配置复跑的实测范围内。
剩余布局 10 右腕为 1.45/255，同配置实测最大值为 1.43/255。
目前 4 次设置用于实验，默认维持 40 次。

`stack_bowls` 的同卡四环境配对也使用了本 PR 的重置配置与相同的 PT16 策略图像设置。
40 次与 4 次采图分别用时 63.11 和 36.27 秒完成重置。布局 11 从第 623 步成功变为
第 800 步超时，成功率从 100% 降到 75%，平均分从 100 降到 78.75。
两组客户端总耗时分别为 399.77 和 429.73 秒，4 次配置的吞吐为 0.930 倍。
三个视角的四布局首帧 MAE 为 0–0.029/255。另一轮 40 次采图的四环境闭环得分为 53.75，
显示原配置的成绩也有波动。当前证据支持保留 40 次的默认配置。

同一倒水任务还对比了 `defer_usd_writeback`，两组都保留 40 次重置采图。
延迟写回将动作执行从 199.11 降到 160.43 秒，客户端总墙钟从 445.03 降到 391.85 秒。
